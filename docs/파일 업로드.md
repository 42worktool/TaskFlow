# 파일 업로드

카드 첨부파일과 아바타 업로드는 [multer](https://github.com/expressjs/multer)로 구현되어 있다. `multipart/form-data` 요청을 파싱해서 로컬 디스크(컨테이너 내부 `/app/uploads`, named volume `uploads_data`)에 저장하는 Express 미들웨어다. 컨테이너를 지우고 다시 만들어도 파일이 유지되도록 `docker-compose.yml`에서 전용 volume으로 마운트한다.

## 사용하는 기능

- `multer.diskStorage()` — 저장 위치/파일명 지정 (`backend/src/lib/upload.ts`의 `storageFor()`). 파일명은 `randomUUID() + 확장자`로 생성해서 충돌·경로 조작을 막는다.
- `limits: { fileSize }` — 업로드 용량 제한
- `fileFilter` — MIME 타입 화이트리스트 검사, 허용 안 된 타입이면 업로드 자체를 거부
- `multer({...}).single('file')` — 라우터에 미들웨어로 꽂으면 컨트롤러 진입 전에 `req.file`에 경로/원본 파일명/크기/mimetype이 채워짐

## 용량 제한 변경하기

제한 값이 3곳에 나뉘어 있고, 그중 2곳이 실제로 강제한다.

### 1. 실제로 막는 곳 — 백엔드 `multer` 설정

`backend/src/lib/upload.ts`
```ts
const ATTACHMENT_MAX_BYTES = 10 * 1024 * 1024   // 첨부파일
const AVATAR_MAX_BYTES = 3 * 1024 * 1024        // 아바타 (별도 값)

export const attachmentUpload = multer({
  storage: storageFor('attachments'),
  limits: { fileSize: ATTACHMENT_MAX_BYTES },   // 여기서 실제 강제
  fileFilter: fileFilterFor(ATTACHMENT_MIME_ALLOWLIST),
})
```
이 상수만 바꾸면 서버가 실제로 거부하는 기준이 바뀐다.

### 2. 같이 바꿔야 하는 곳 — nginx

`nginx/default.conf`
```
client_max_body_size 10m;
```
nginx가 백엔드보다 먼저 요청을 받기 때문에, 이 값이 `ATTACHMENT_MAX_BYTES`보다 작으면 nginx가 먼저 요청을 잘라버려서 백엔드 설정을 올려도 소용없다. 예를 들어 20MB로 늘리려면 여기도 `20m`으로 같이 올려야 한다.

### 3. UX용 (강제력 없음) — 프론트엔드

`frontend/src/utils/uploadLimits.ts`
```ts
export const ATTACHMENT_MAX_BYTES = 10 * 1024 * 1024
```
서버에 요청 보내기 전에 미리 "10MB 넘었어요"라고 즉시 알려주는 용도일 뿐, 실제 방어선은 아니다(클라이언트 검증은 우회 가능). 안 바꿔도 업로드 자체는 되지만, 사용자에게 잘못된 제한을 안내하게 된다.

**정리**: 제한을 바꾸려면 `backend/src/lib/upload.ts` (실제 강제), `nginx/default.conf`의 `client_max_body_size` (nginx가 먼저 자름), `frontend/src/utils/uploadLimits.ts` (안내 문구용) 세 곳을 같은 값으로 맞춰야 한다.

## 접근 제어

- **카드 첨부파일**: 인증 + 워크스페이스 멤버십 확인이 붙은 다운로드 라우트(`GET /api/cards/attachments/:id/download`)를 통해서만 접근 가능. 업로드/삭제는 `MEMBER` 이상만 가능 (VIEWER는 프론트/백엔드 모두에서 차단).
- **아바타**: 인증 없이 공개 서빙(`/uploads/avatars/...`). 이미 앱 전역에서 `profile_image_url`을 평범한 `<img src>`로 노출하고 있고(Google OAuth 아바타도 원래 공개 URL), 추측 불가능한 UUID 파일명을 쓰기 때문에 기존 노출 수준과 동일하게 맞춘 설계다.

## 실패 시 파일 정리

멀티파트 업로드는 컨트롤러 로직이 실행되기 *전에* multer가 이미 디스크에 파일을 써버린다. 그래서 이후 단계(권한 체크, DB 저장 등)가 실패하면 방금 쓴 파일이 고아 상태로 남을 수 있다. `backend/src/lib/upload.ts`의 `withUploadCleanup()` 헬퍼가 이 경우 파일을 정리한다 — `card.controller.ts`의 `addAttachment`와 `auth.controller.ts`의 `uploadAvatar` 양쪽에서 사용.
